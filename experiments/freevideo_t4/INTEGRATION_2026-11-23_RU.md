# Freevideo — экспериментальная интеграция гибридного I2V-конвейера

Дата: 23 ноября 2026 года. Цель: объединить существующие компоненты
Two Worlds Studio и Freevideo **только** внутри
`research/freevideo-t4-adaptive-20261123`, не изменяя production-код.

## Что реально реализовано

1. `hybrid_engine.py` — отдельный управляющий маршрут
   `prepare → preview → review-template → final → status`.
   Не переписывает существующие `studio/**` компоненты, а повторно использует
   их в режиме чтения/локального нейросетевого исполнения через имеющийся bridge.
2. `studio.video_ai_plan._reference` — настоящий Studio-контракт 9:16.
   Источники 3:4 адаптируются без обрезки: оригинальные лицо, пальцы и обувь
   остаются в кадре. Исходный файл не перезаписывается, SHA-256 фиксируется.
   Это **НЕ нейросетевая анимация**, только подготовка входного изображения.
3. `adaptive_pipeline.run` — единственный разрешённый нейросетевой маршрут.
   Проверка фактической T4, памяти, локального ComfyUI, SHA-256 трёх файлов
   весов, эксклюзивной блокировки одной карты, quarantine после неизвестного
   состояния задания, подтверждения кадров и квитанций.
4. `studio.comfy_neural` — уже существующий реальный I2V Wan2.2-5B
   backend. Никаких Runway, InVideo, ElevenLabs или внешних AI API.
5. `quality_metrics.audit_video` — полная CPU-декодировка MP4, проверка
   времени/кадров, флаги аномалий движения (НЕ художественное одобрение).
6. `studio.video_qc.sample_video` — дополнительные исторические метрики
   студии; отсутствие их результата не отменяет уже созданный нейросетевой
   MP4, но записывается отдельно.
7. `*.hybrid.json` — защищённая новая квитанция, привязанная к source,
   reference, Studio receipt и Freevideo receipt. Никаких автоматических
   `human_approved=true`, публикаций или скрытых повторных запусков.
8. `kaggle_private_job.py` — упаковщик исходного PNG в **приватный** Kaggle
   скрипт. Создаёт приватный `kernel_main.py` (фото не попадает в GitHub).
   Фиксирует Git SHA, проверяет условия модели, требует явного разрешения
   на использование официальных весов. Сам упаковщик GPU-квоту не расходует.
9. `kaggle_worker_template.py` — приватный Kaggle T4 worker. Использует
   официальный Kaggle GPU, локальные ComfyUI/Wan2.2 (без AI API), проверяет
   именно заданный Freevideo commit, создаёт реальный preview через
   `hybrid_engine` и сохраняет отдельные оригинальные приватные отчёты.
10. `kaggle_private_job.verify_private_result` — отдельная проверка
    результатов: SHA ZIP, взаимная согласованность Studio/Freevideo/hybrid
    квитанций, полная CPU-декодировка всех кадров. Поддельный MP4
    отбрасывается. Сам факт декодировки не доказывает художественное качество.

## Испытания и их границы

**CI**: GitHub Actions `freevideo-t4-offline.yml`. Запускать:
`python -m unittest discover -s experiments/freevideo_t4 -p 'test_*.py' -v`.
Новые тесты проверяют частный вход, отсутствие обрезки, иммутабельность
фото, отказ без разрешения на GPU, загрузку Studio-контракта, реальное CPU
декодирование синтетического MP4, корректность ссылок квитанций,
неподдельность ZIP, неизменность `main`, отказ от автоматического review.

В изолированных CI используется **MOCKED inference** и настоящие
синтетические файлы MP4/PNG для CPU-тестов. Эти результаты не являются
нейросетевыми роликами.

| Критерий | Статус |

| Оркестрация Freevideo + существующий Studio мост | IMPLEMENTED |

## Серьёзные ограничения, оставшиеся после интеграции

- Гибридный конвейер **объединяет существующие компоненты**, но не является
  нейросетью с объединёнными весами Wan/VDN. В этой ветке только один
  neural backend: локальный Wan2.2 TI2V-5B.
- Real-T4 не запускался в контексте данного этапа; нельзя утверждать,
  что `432×768, 25 кадров` помещается в текущую загрузку видеопамяти.
- `kaggle_worker_template.py` предполагает официальный приватный Kaggle
  internet-enabled kernel, достаточную RAM/диск и скачивание больших весов.
  Kaggle может не выдать GPU или завершить сессию; тогда статус BLOCKED.
- Приватный worker выдаёт **первый Preview**. Final разрешён только после
  независимого просмотра preview и ручного утверждения, с отдельной проверкой.
- Автоматические пиксельные измерения не определяют сохранность личности
  и не отличают реалистичную артикуляцию от смещения камеры с гарантией.
- В предложенной упаковке первоначальное фото встроено в **приватный**
  Kaggle kernel_main.py. Публичная публикация kernel запрещена.
- Никто не должен скачивать/повторно запускать веса за счёт аккаунта
  без законной лицензии и свободной квоты.
- Статус `GPU_BRIDGE_REPORTED` — это результат native bridge receipt;
  независимое свидетельство работы чипа требует самого Kaggle run ID,
  системных логов и метрик VRAM.

## Что требуется для настоящего ролика по присланному фото

Приватный Kaggle kernel c реальной T4 и установленными официальными
Wan2.2 checkpoint файлами. Загрузить/выполнить через официальный Kaggle
CLI и только в приватном kernel, затем сохранить
`FREEVIDEO_PRIVATE_PREVIEW.zip`, `freevideo_result.json` и точный
Kaggle run ID. Проверить полное MP4 и внешность персонажа человеком,
исключить плавание и обрезку исходника. Если первый preview удовлетворяет
качеству — независимо разрешить отдельную генерацию Final.

**Не выдавать существующий локальный procedural-проектор статической
картинки за результат Freevideo neural inference.**

ИТОГ: новая оркестрация и подготовка Kaggle **реализованы**; реальный
готовый нейросетевой рекламный ролик без фактического Kaggle GPU прогона
**не создан**, художественная пригодность **не проверена**.
