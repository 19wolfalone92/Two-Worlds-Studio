# Кинематографическая сборка TWO WORLDS STUDIO

Маршрут `produce` собирает утверждённый монтажный список из локальных материалов, экспортирует MP4 и проверяет декодированный файл. Старые манифесты `schema: 1` и прежние команды доступны для воспроизведения старых сборок.

## Запуск

Установите Python 3.11+, FFmpeg с libx264 и libass, ffprobe и шрифт DejaVu Sans. В корне репозитория выполните:

```bash
python -m pip install -e '.[validation]'
python -m studio.cli doctor
python -m studio.cli produce \
  --manifest ../my-film/edit.json \
  --output ../my-film/review.mp4 \
  --cache ../my-film/private-cache
```

Храните проект, кэш, референсы, звук и выходные файлы вне checkout. После успешной сборки рядом с MP4 появятся SRT и JSON. JSON содержит бэкенд каждого кадра монтажа, причину переключения на риг, сведения о дорожках и технический QC. Если экспорт блокируется, CLI возвращает код 2. Статус `PASS` относится к технической проверке. Итоговое `REVIEW REQUIRED` означает, что сцену можно открыть для оценки монтажа, актёрской игры, речи и сюжетных деталей.

## Материалы новой сцены

1. Возьмите утверждённые сцены и реплики. Сделайте раскадровку с последовательностью планов, референсами персонажей, длительностью и временем появления подсказок.
2. Подготовьте PNG, клипы и WAV в папке монтажного списка. Базовые ключи манифеста — `schema: 1`, `width: 1080`, `height: 1920`, `fps: 30`, `language: "ru"`, `burn_subtitles: true`, `shots`.
3. Для каждого кадра монтажа задайте `image` или `clip`, `duration` в секундах и `shot_type`. Для реплики укажите `voice`, при необходимости `voice_offset` и `voice_bus` (`dialogue` или `narration`), а также `subtitle_cues` с локальным временем и точным текстом. Если задан `dialogue_text`, слова в субтитрах проверяются по нему.
4. Разложите окружение по слоям `cinematic.layers`. Задайте глубину, камеру, рисунки частей рига и ключевые позы. Для рисованных персонажей достаточно прозрачных PNG и конфигурации `CharacterRig`. Мягкую деформацию единого спрайта включает `deform` с дополнительной зависимостью `python -m pip install -e '.[cinematic]'`.
5. Добавьте `sound_stems` с полями `bus` (`music`, `ambience` или `sfx`), `path`, `start` и `gain`. Дорожки сводятся по времени монтажа, а музыка и фон приглушаются во время речи. Для записанного голоса есть флаг `voice_cleanup`. Оставляйте его выключенным для чистого синтеза.

### Выбор анимации

- `animation_backend: "rig"` использует слои и риг. Положение камеры и движение костей рассчитываются отдельно для каждого кадра.
- `animation_backend: "i2v"` требует готовый дубль LTX в `i2v.clip` и JSON от `studio.neural_motion.render_clip` в `i2v.receipt`. Студия сверяет SHA-256 клипа и референса, число декодированных кадров и длительность.
- `animation_backend: "auto"` выбирает пригодный дубль. Если дубль недоступен, сборка применяет заданный риг и записывает причину в отчёт. Загрузка моделей и запуск вычислений выполняются отдельно. Сначала проверьте доступные CUDA, память и квоту в разрешённой среде. Подключение нового видеобэкенда требует пробного прогона на доступном оборудовании.

Для сюжетной детали укажите её идентификатор в `required_clues` и задайте в соответствующем плане `protected_regions`. У каждой области есть `id`, индекс `layer`, нормализованный прямоугольник `box: [x0, y0, x1, y1]` и окно `start`–`end` в секундах этого плана. При пересечении с зоной титров можно выбрать `caption_position: "top"`. Камера и наложение непрозрачных слоёв проверяются для каждого кадра указанного окна. Визуальный смысл подсказки сверяется при просмотре.

### Оптика и проверка движения

В `cinematic.optics` задайте `focal_mm`, `aperture` и `focus_m`. Для портретного кадра по умолчанию используется ширина сенсора 24 мм. У каждого слоя укажите `distance_m`. Например, для крупного плана подходят 85 мм, f/3.5 и фокус 1.8 м при фоне на 6 м. Для общего плана начните с 35 мм и f/4. Камеру и кадрирование задавайте отдельно. Профиль рассчитывает расфокус плоскостей по модели тонкой линзы. Значение `shutter_angle: 144` добавляет три пробы экспозиции из той же траектории движения. По умолчанию угол 0. Защищённая подсказка остаётся резкой, а в её окне используется одна проба.

На слое можно задать `required_focus_box: [x0, y0, x1, y1]` вокруг важной детали на исходном PNG. Preflight проверит текстуру непрозрачной части и остановит сборку при сильной размытости. Для каждого плана `qc_regions` задаёт области уже в координатах выходного кадра. Например, `{"id":"mark-face","kind":"face","box":[0.18,0.36,0.70,0.65],"motion_required":true}`. Укажите 1–6 областей типа `face`, `hands`, `prop` или `background`. `motion_required` включайте там, где по замыслу нет длительных стоп-кадров. Для намеренного мерцания задайте `allow_exposure_change: true`.

Студия декодирует каждый кадр этих областей, оценивает межкадровый сдвиг и записывает интервалы с нарушениями. Подозрительные изменения и низкая уверенность требуют просмотра. Зависание обязательного движения и сильное повторное мерцание блокируют экспорт. Геометрию лица, кисти и перспективу проверяют при просмотре. Для отдельного короткого клипа используйте `python -m studio.video_qc --video take.mp4 --regions-json regions.json`, где `regions.json` содержит сам массив областей.

### Речь и синхронизация губ

Входом служит настоящий WAV. Маршрут `voice-plan` использует существующую регистрацию голосов Qwen для русского и Kokoro для английского. Генерация Qwen требует отдельно установленных PyTorch и `qwen-tts`. Прослушайте результат перед монтажом.

```bash
python -m studio.cli voice-plan --speaker Elizabeth --language ru \
  --text-file ../my-film/line.txt --execute --allow-model-load \
  --output ../my-film/line.wav

python -m studio.cli run --engine lipsync --execute -- \
  --voice ../my-film/line.wav --rhubarb /opt/rhubarb/rhubarb \
  --output ../my-film/line.visemes.json
```

В слое говорящего персонажа укажите `facial.viseme_track` и `facial.mouth` с зарегистрированными PNG формы рта. Для Rhubarb предусмотрены формы A–H и `rest`. Каждый PNG содержит `path` и `sha256`. Свяжите WAV с планом через `voice`. Если собеседник говорит в другом плане, закрепите его реплику за соответствующим ригом там. Рисованные формы привязаны к голове, а анализ WAV закрывает рот во время пауз. Rhubarb даёт приближённые формы для русской речи. Для точных таймингов используйте проверенный трек артикуляции и оцените результат в крупном плане.

### Фонемная артикуляция в русских крупных планах

Для точной привязки к реплике подготовьте WAV и текст из `dialogue_text`. В отдельно установленном Montreal Forced Aligner (MFA) выровняйте запись с русской акустической моделью и словарём. Проверенная конфигурация использует MFA 3.4.3 и модели Russian MFA v2.0.0a. Лицензию и атрибуцию модели см. в [карточке Russian MFA](https://mfa-models.readthedocs.io/en/latest/acoustic/Russian/Russian%20MFA%20acoustic%20model%20v2_0_0a.html).

```bash
mfa align_one --output_format json line.wav line.txt russian_mfa.dict russian_mfa.zip line.mfa.json
python -m studio.cli run --engine lipsync --execute -- \
  --voice line.wav --mfa-json line.mfa.json --text-file line.txt --output line.phones.json
```

В `facial` говорящего слоя укажите `phoneme_track: "line.phones.json"` и `mouth_mesh`. В `mouth_mesh.seam` задайте 3–12 точек линии сомкнутых губ слева направо. Координаты относительны ко всему холсту рига до поворота головы. `max_open` задаёт верхний предел раскрытия в долях ширины губ. Начальное значение `0.20` подходит для сдержанной речи. В фотореалистичном плане в три четверти задайте `opening_peak` в пределах 0.25–0.75 ширины шва. Это смещает максимальное раскрытие к видимому центру рта и берёт цвет внутренней части из исходного изображения. Для этого слоя используйте один источник артикуляции.

Студия проверяет соответствие фонемного трека WAV и исходному тексту. Фонемы управляют плавным раскрытием и округлением губ. Смыкание сохраняется на «м», «б» и «п», а в измеренных паузах восстанавливается исходная форма. Режим `mfa_phoneme_mesh` работает на CPU и появляется в отчёте плана. Просмотрите мимику на исходном крупном плане.

## Проверка и восстановление

`produce` проверяет полный MP4, чёрные кадры, кадровый тайминг, AAC, пиковый уровень, громкость и SRT. При отклонении громкости после динамической нормализации студия может выбрать постоянное усиление, если повторное измерение подтверждает запас по пику. Отчёт содержит метод мастеринга, измерения PCM и показатели AAC из готового MP4. Контактный лист можно снять командой `python -m studio.delivery_qc --video ../my-film/review.mp4 --output ../my-film/qc.json --review-board ../my-film/board.png`.

Если реплика закреплена через `dialogue_text`, студия ищет фрагмент исходной волны в декодированном AAC. Уверенно найденный сдвиг больше одного кадра блокирует сборку. Слабое совпадение требует прослушивания. Проверка касается тайминга и не оценивает дикцию или актёрскую игру.

После прерывания запустите ту же команду с прежним `--cache`. Совпадающие проверенные сегменты будут использованы повторно. Битый сегмент пересоберётся. После ошибки исполнителя действует ограниченная задержка повтора. Если процесс аварийно завершился, новая попытка получит задачу после истечения аренды. Для новой версии результата укажите новое имя MP4 и сохраните тот же путь к кэшу.

Файл `MASTER_SCREENPLAY_FINAL` v1.1 хранится вместе с материалами «АРХИВА 17». Используйте его и соответствующую карту подсказок как входы редакторской подготовки.
