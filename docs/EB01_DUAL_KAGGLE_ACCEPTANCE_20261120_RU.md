# Elizabeth Bones — приёмка двух Kaggle-аккаунтов

Дата проверки и получения файлов: **20 ноября 2026 года, Минск**.
Проект: только Two Worlds Studio / Elizabeth Bones «Собеседование».

**Оба независимых аккаунта работают. Два настоящих нативных MP4 получены и
проверены. Художественная приёмка не пройдена: движение почти статично,
русская речь не управляет анимацией. Полный производственный рендер запрещён.**

## 1. Реально выполненные действия

- Авторизация двумя различными токенами; проверено различие учётных записей.
- Каждый аккаунт самостоятельно скачал общий приватный исходник: два портрета
  и шесть оригинальных WAV. Все восемь SHA-256 совпали с каноном на обоих
  аккаунтах. Это проверка байтов, а не только списка файлов.
- Проведены два настоящих GPU-пилота на закреплённой версии студии
  `75115ac6e6b63dae25e879ea86d32cf015bda49c` и официальном LTX
  `50f0aef1297574a4b29acbdb874e3a363a6d5f2e`.
- Существующие задания забраны повторно без новой генерации. Оба находятся
  в состоянии `COMPLETE`. После первого мониторинга они оставались `QUEUED`;
  эта очередь не доказывала ни запуск модели, ни её ошибку.
- Каждый MP4 повторно декодирован вне генератора. Проверены геометрия,
  хронометраж, SHA, все кадры, цвет и точные повторы RGB.
- Созданы два отдельных долговечных SQLite-журнала по 15 будущих дублей.
  Производственных заданий отправлено **0**.

## 2. Исправленные ошибки и первопричины

| Ошибка | Исправление и проверка |
|---|---|
| Видимость списка файлов считалась достаточной для проверки общего исходника | Независимое скачивание обоими токенами и SHA всех восьми оригиналов |
| Процесс Kaggle наследовал лишние секреты и старые настройки авторизации | Изолированная среда с одним выбранным токеном и отдельным временным каталогом конфигурации |
| Путь тайлинга закреплённого VAE терял параметры декодирования | Передача timestep и нормализации через тот же `_decode`, коррекция пространственного масштаба; реальная генерация обоих MP4 завершилась |
| Повторная GitHub-приёмка возвращала `NeuralBlocked`, хотя видео существовало | Установка FFmpeg/ffprobe в обоих workflow; повторная фактическая приёмка прошла |
| Основной CI падал при импорте проверки WAV | Добавлена зависимость `soundfile` |
| FFmpeg 7 при passthrough записывал нулевую длительность последнего пакета | Явная временная шкала MP4: 24 тика/секунду; сохранены ровно 33/32 кадра и правильная длительность |
| Повтор после истечения мониторинга мог породить лишний рендер | Режим collection читает тот же исходный run и revision; повторных GPU-submit нет |
| Валидный видеоконтейнер мог скрывать повторение кадров | Добавлена проверка хешей реальных декодированных RGB-кадров; синтетический неподвижный тест обнаруживает 32 повтора |
| Не было отдельного устойчивого состояния двух очередей | SQLite/WAL/FULL, атомарный захват, неизменяемый аккаунт, nonce, предшественник и состояние неопределённой отправки |

## 3. Авторизация и приватные исходники

Проверка [43917247939](https://github.com/19wolfalone92/Two-Worlds-Studio/actions/runs/43917247939)
подтвердила два разных авторизованных аккаунта, скачивание и SHA восьми
файлов на каждом, без HTTP 403. Общий хеш канонического перечня:
`1c0cc4b4d1e4f6842585ec4a16dd6af30fa4245e2437e54bf935743f6cb16109`.

При сборе результата 20 ноября оба токена снова авторизовались и получили
собственные приватные GPU-выводы. Метаданные обоих notebooks подтвердили
`is_private=true`, `enable_gpu=true`, `machine_shape=NvidiaTeslaT4`.

Датасеты не переводились в Public. В открытые GitHub-артефакты не отправлены
портреты, WAV, открытые MP4 или ключ расшифрования. Возврат результатов
использует уже существующий механизм RSA-3072/OAEP + AES-256-GCM; открытый
runner получает только публичный ключ. Отдельная проверка анонимного ACL
самого датасета в этой итерации не проводилась; успешная авторизация не
подменяет такую проверку. Токены не извлекались из GitHub secrets.

существующие результаты и фактические журналы двух завершённых пилотов.

Подтверждены **четыре отдельные T4**. Память между ними не объединялась.
Один процесс использовал GPU 0; GPU 1 оставался практически незадействован.
Два тяжёлых процесса внутри одного аккаунта не проверены. Их одновременный
пик RAM нельзя считать допустимым при имеющемся лимите около 31 ГиБ.

Kaggle предоставляет меняющиеся квоты и очереди; остаток каждой личной
квоты через эти проверки не измерен. Нельзя вычитать длительность очереди
из GPU-квоты или объявлять стандартную недельную квоту её текущим остатком.
Официальные ограничения: [Notebooks](https://www.kaggle.com/docs/notebooks),
[GPU usage](https://www.kaggle.com/docs/efficient-gpu-usage).

## 5. Проверенная конфигурация видеогенерации

- Официальный LTX Video 2B distilled, закреплённые исходники, 8 шагов.
- Нативные **576×1024**, **33 кадра**, **24 FPS**, conditioning noise 0,15.
- Входной кадр получен прямо из исходного портрета 704×1216; производная
  картинка 320×576 не увеличивалась для имитации нативной детализации.
- Transformer и T5 — FP16; VAE — FP32, чтобы сохранить проверенный путь
  декодирования без прежних цветовых переполнений.
- Последовательная загрузка T5 → conditioning VAE → transformer → VAE decode
  с CPU offloading и освобождением CUDA-кэша между этапами.
- Пространственный тайлинг VAE 256 пикселей с перекрытием 25%.
  Временной тайлинг отключён, чтобы не терять причинный контекст между кусками.
  Batch равен 1; slicing по batch дополнительной экономии здесь не даёт.
- Attention использует upstream PyTorch SDPA; конкретный CUDA backend
  отдельно профилировщиком не подтверждался. FlashAttention не объявлен
  работающим лишь по наличию GPU.
- Квантование не применялось: эта 2B-конфигурация уже помещается на одной
  T4. Непроверенная экономия за счёт ухудшения картинки не выдается за улучшение.
- Необязательное расширение prompt через Florence/Llama отключено.
- Сохранены исходные MP4, safetensors перед декодированием и контекст/хеш
  checkpoint. Отдельное GPU-восстановление декодера из checkpoint ещё не
  испытано; перезапуск очереди и возврат уже существующих MP4 испытаны.

**Сейчас доказан режим одного процесса на аккаунт.** Оптимум для четырёх
одновременных генераторов не доказан. Повторное использование моделей в
долгоживущем производственном worker пока не испытано: выполнены отдельные
короткие пилоты. Полноценного производственного dispatcher в этой итерации нет.

`9667a266da56dd74251470220f5efdd698cc52722e2b054aca5092a037337e45`.

`deca5ce740e8980cb538b542968c681991b7985681b331d3c82ce7b705775ca1`.

использовались как доказательство. Кадры действительно различаются, однако
эта разница слишком мала для утверждения о естественной актёрской игре.

## 7. Оценка качества

- Картинка и внешний облик визуально стабильны на коротком интервале.
  Видимых полос/неоновых повреждений на проверенных кадрах не найдено.
- Костя практически неподвижен. Движение костной челюсти, шеи, плеч и рук
  для разговора не продемонстрировано.
- У Елизаветы есть небольшие изменения лица, но выраженная естественная
  работа головы, плеч, рук и тела не продемонстрирована.
- В пилотах нет аудиопотока. Наличие исходных русских WAV и совпадение их
  SHA не доказывает синхронизацию губ. Модель I2V не получала русскую речь
  как управляющий вход.
- Художественный результат **отклонён как почти статичный**. Контактные
  листы просмотрены ассистентом; независимая человеческая экспертная
  оценка и одобрение владельца не проводились.
- Межсценная стабильность, полноценная физика, отсутствие долгих временных
  деформаций и речь требуют более длинного самостоятельного пилота.
  Эти 1,375 секунды не заменяют приёмку 2–4 секунд разговора.

## 8. Распределение 30 дублей и восстановление

| Очередь | Сцены и количество оригинальных дублей | Итого |
|---|---|---:|
| Первый аккаунт | S01 — 4; S02 — 6; S04 — 5 | 15 |
| Второй аккаунт | S00 — 3; S03 — 3; S05 — 5; S06 — 4 | 15 |

Все 30 идентификаторов различны. Сцена закреплена за одним аккаунтом;
следующий дубль зависит от проверенного PNG последнего кадра предыдущего.
Начатая сцена не мигрирует при потере квоты или доступа.

SQLite использует атомарную транзакцию, уникальный nonce, журнал событий,
WAL и `synchronous=FULL`. Неопределённая отправка остаётся `UNCERTAIN`;
перезапуск не превращает её в новый submit. Перед записью результата
перепроверяются SHA реального MP4/PNG, нативные кадры, цвет и совпадение PNG
с фактическим последним RGB-кадром. Эта техническая запись сама по себе
не является художественным одобрением. Подготовленные базы содержат
только по 15 `PENDING`, без созданных production kernels.

## 9. Условная оценка ресурсов полного фильма

План требует 30 оригинальных сегментов, 967 финальных кадров и 40,292 с.
Если будущие одобренные сцены будут иметь ту же стоимость, что эти два
пилота, грубая оценка — **84,13 мин** для первого аккаунта и **79,64 мин**
для второго: суммарно **163,77 мин** работы процессов инференса.
При одновременной работе двух аккаунтов нижняя оценка — около **84 мин**
плюс очереди, подготовка моделей, проверка и сборка. С резервом 1,5×
следует предусмотреть **126,19 / 119,46 мин** на аккаунт.

Это экстраполяция двух почти статичных пилотов, а не измерение стоимости
качественного фильма и не подтверждение доступного остатка квоты. Замена
модели или добавление аудиоуправляемой анимации потребует нового измерения.
Все RGB-кадры 30 сегментов заняли бы около 1,63 ГиБ без сжатия; потоковая
обработка позволяет не держать их одновременно. Размер качественного
MP4 нельзя надёжно вывести из двух почти неподвижных коротких клипов.

## 10. Что готово и что остаётся

Готовы: независимые токены и доступ к оригиналам, проверенная техническая
генерация 576×1024 на двух аккаунтах, частный возврат оригиналов, контроль
SHA/RGB/времени/памяти, раздельные устойчивые очереди и проверки восстановления.

Остаются: естественная актёрская анимация, реальное управление русской речью,
одобренный более длинный пилот, актуальная квота каждого аккаунта,
эксперимент с двумя тяжёлыми процессами в одном сеансе, GPU-проверка
восстановления декодера и долгоживущий production worker. Полный фильм
**не создан**, его качество и срок готовности не обещаются.

Работа остаётся в отдельной ветке; main не изменён. Ничего не отправлялось
в TikTok, платные GPU-сервисы не использовались.
