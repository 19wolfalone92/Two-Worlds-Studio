# Studio 5.0 · постановка, движение и выпуск

`python -m studio.cli produce` остаётся единой точкой входа для монтажного манифеста. Она использует слои `cinematic`, преобразования `character_engine`, синхронизацию `facial_actor`, локальные клипы Blender и проверенные готовые I2V-дубли. Рендер эпизодов через `studio.render` также передаёт частоту кадров в композитор.

| Воспроизводимая проблема | Изменение |
| --- | --- |
| Разность кадров росла при одном движении камеры | Движение в зоне действия теперь измеряется относительно декорации или части головы. |
| Короткий клип добирал недостающие кадры остановкой | Зарегистрированные клипы и клипы с ожидаемым действием проверяются по видео. Нейромонтаж больше не дополняет движущийся дубль стоп-кадром. |
| Готовый покадровый слой мимики требовал отдельной сцены | Основной композитор принимает RGBA-патчи на закреплённом портрете и переносит их вместе с ригом. Кэш учитывает файлы и монтажный профиль. |
| Движение могло упереться в пределы параллакса | Нормированный ход находится в границах исходного кадра. Камера начинает и завершает движение с нулевой скоростью и ускорением. При неподвижной камере статичные слои проецируются один раз. |
| Запрошенный стиль Qwen мог читаться в отчёте как использованный | Отчёт различает запрос и отправку инструкции. Английский каст Kokoro отклоняет кириллицу до синтеза. |

## Режимы и мимика

Необязательный `visual_profile` принимает `photoreal_cinematic`, `stylized_cinematic` и `3d_character`. Старые манифесты продолжают использовать привычный маршрут. Фоновые слои идут в кинематографический композитор. Части и деформируемые области используют риг. Зарегистрированная мимика работает поверх рига. I2V требует существующего подтверждения LTX. Зарегистрированные готовые клипы указывают `clip_take` с `engine` (`blender_3d` или `neural_character`), `visual_profile` и `sha256`. Фотореалистичный автоматический режим при наличии обоих вариантов выбирает закреплённый артикулированный портрет. Профиль 3D требует клип Blender для планов персонажей. Проверка хеша и заявленного профиля не является художественной оценкой.

У слоя `character` с `rig` задайте `facial.performance_take` с относительным `path` к JSON и его `sha256`. Режим мастера дополнительно проверяет декларацию происхождения и подтверждение просмотра. В JSON нужны следующие поля.

- `schema: 1`, точный `fps`, `canvas` с размером портрета и `box` в пикселях `[left, top, right, bottom]`.
- `portrait_sha256` и `head_sha256` привязывают результат к текстурам.
- `speech: null` для движения без речи. Для речи передаются `wav_sha256`, `text_sha256` точного текста в UTF-8 и `offset_ms`. Поле `facial.phoneme_track` задаёт разметку, привязанную к тому же WAV и реплике.
- `frames` содержит ровно столько элементов, сколько кадров в плане. Элемент `null` сохраняет исходную текстуру. Объект с `path` и `sha256` указывает локальный RGBA PNG. Патч ограничен альфа-каналом исходной головы.

В этой цепочке импортируется готовая последовательность. Генератор модели, веса и художественное подтверждение ведутся отдельно. Хеши голоса и разметки фиксируют тайминг. Оценка дикции и качества артикуляции требует просмотра.

## Проверка результата

`qc_regions` принимает одну область `kind: "camera"` на неподвижной части декорации. Области действия могут задавать `motion_windows` с `start` и `end` относительно начала плана. Области глаз и рта ссылаются через `relative_to` на устойчивую часть головы. Лицо и одежда могут указывать `identity_reference` с `path`, `sha256` и нормированным `box` в исходнике.

Оптический поток анализирует соседние кадры. Для неподтверждённого движения, потери опоры, движения рта на тихом участке и слабого совпадения геометрии текстуры требуется ручная проверка. Диагностика записывает кадры, секунды плана и таймкоды на общей шкале. Для оптического потока и сравнения текстур нужны зависимости `.[cinematic]`. Без них статус проверки движения `REVIEW REQUIRED`. После монтажа отдельно проверяются кадры, яркость и цвет, полнота декодирования и положение исходных реплик в AAC.

`--cache` хранит каждый подтверждённый сегмент по хешам исходников и версии рендера. После изменения одного плана пересчитывается его сегмент. Готовые сегменты других планов читаются из кэша, а мастер собирается заново. Существующие ограничения на видимость подсказок и субтитры применяются.

```bash
python -m compileall -q studio tests
python -m unittest discover -s tests -v
python -m unittest discover -s tests -p 'test_verified_cinematic.py' -v
python -m studio.cli produce --manifest /path/to/private/shotlist.json \
  --output /path/to/private/review.mp4 --cache /path/to/private/cache
```
