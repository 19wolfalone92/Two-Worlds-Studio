# TWO WORLDS / STORY GLITCH — приватный автономный Batch03 (№13–18)

**Назначение:** не переписывать существующие шесть русских Work-историй, а самостоятельно собирать MP4, когда реальные кадры и русские голоса поступили в приватную очередь. Эта реализация не утверждает, что шесть исходных MP4 уже существуют, и не запускает платные API, публикацию или GPU.

## Что реально автоматизировано без Work

- Проверка исходных историй №13–18: неизменённость текста по SHA-256, корректные приватные пути, наличие всех восьми и более сцен, изображений, голосов и субтитров.
- Техническая проверка полноценной комплектности через `studio.shorts_factory.validate_project`.
- CPU/FFmpeg-сборка через `studio.shorts_factory.run`: стабильное движение камеры, вшитые русские субтитры, H.264/AAC, цветная обложка, проверка видео на чёрные кадры, receipt c SHA-256.
- Сохранение состояния при рестарте: готовые MP4 не перезаписываются; повреждённые, подменённые файлы и чёрные обложки блокируются.
- Режим `watch` с повторной проверкой и CPU-рендером по мере поступления реальных медиа. После шести технически валидных роликов останавливается.
- JSON-статус содержит только номера, количества и коды задач; приватные сценарии, аудио и токены в отчёте отсутствуют.

## Команды

Только на **приватной машине или приватном runner** с Python 3.11+, Pillow, FFmpeg/ffprobe и libass:

```bash
python -m studio.shorts_batch --kit /private/Story_Glitch_Batch03_RU_Production_Kit --out /private/queue

# Без изменения данных и квот
python -m studio.autonomous_batch --queue-root /private/queue --out /private/exports --mode status

# Один проход: не более двух готовых роликов
python -m studio.autonomous_batch --queue-root /private/queue --out /private/exports --mode render --max-jobs 2 --report /private/status.json

# Повторяет проверку каждые 10 минут, собирает по одному готовому ролику
python -m studio.autonomous_batch --queue-root /private/queue --out /private/exports --mode watch --max-jobs 1 --interval-seconds 600 --report /private/status.json
```

Ожидаемые статусы: `WAITING_FOR_PRIVATE_SOURCE`, `ASSETS_PENDING`, `READY_TO_RENDER`, `REVIEW_REQUIRED`, `INPUT_BLOCKED`, `OUTPUT_BLOCKED`. Поле `next_action` объясняет следующий конкретный этап.

## Важное ограничение

Этот CPU-координатор **не создаёт отсутствующие фотореалистичные PNG и естественные русские WAV**. Для этого уже существует отдельный `studio.kaggle_shorts_worker` (на **приватной** Kaggle GPU-сессии с настоящими доступными весами). 2× T4 — две отдельные карты по 16 ГиБ; бесплатная квота конечна. Синхронизация медиа из приватных результатов Kaggle в локальную очередь пока требует настройки runner и набора реальных приватных исходников.

Наличие автоматического рендера не означает право публиковать: видео остаются `REVIEW_REQUIRED`. Перед TikTok/YouTube/Instagram необходимы проверка голоса, внешнего вида, плавности, лицензий, AI-маркировки, первого **цветного** кадра и цветной обложки. Отдельная обложка в TikTok может быть не принята сторонней интеграцией: цветной первый кадр MP4 обязателен. **Публикация в Metricool/TikTok Studio здесь выключена** во избежание дубликатов и публикации непроверенных историй.

Нельзя отправлять приватный Batch03, новые PNG/WAV/MP4 или ключи в публичный GitHub и публичные GitHub Actions artifacts. Код студии независим от Williams Bot и отдельного сериала TWO WORLDS — THE FRACTURED REALITY.
