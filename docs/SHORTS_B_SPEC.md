# B — техническое задание: Two Worlds Story Shorts Factory

**Назначение.** Из утверждённых русских сценариев Batch 03 (№13–18) и фактически сгенерированных/лицензированных исходных медиа формировать профессионально подготовленные вертикальные ролики для предварительного просмотра. Студия не пишет заново истории, не клонирует чужие голоса и сама не публикует видео.

## B1. Входной контракт v1

`project.json` — UTF-8 JSON с полями:
- `schema: 1`; `id` — безопасный ASCII slug; `title` (русский), `language: "ru"`.
- `script_file` — относительный путь к оригинальному русскому файлу; `script_sha256` — обязательный SHA256 именно его байтов. Скрипт не переписывать.
- `width=1080`, `height=1920`, `fps=24` (в smoke-тестах можно меньшие размеры).
- `scenes` — минимум 8 для полноценной истории, строго уникальные ID.
- Каждая сцена может содержать `motion_video` (необязательный настоящий лицензированный MP4/MOV/WebM): вместо статичного zoompan подставляется исходный видеоклип; проверяется наличие видеопотока и продолжительность не короче озвучки. Никаких зацикленных коротких заготовок, выдаваемых за живую анимацию.
- Каждая сцена: `id`, `image` (реальный PNG/JPEG), `voice` (реальный WAV/M4A/MP3), `subtitles` — список `{start,end,text}` **в секундах от начала данной сцены**, выровненные по реальному аудио; `music` необязателен (лицензированный файл).
- Относительные медиа-пути разрешаются **только** внутри указанной папки проекта; запрет `..`, абсолютных путей и выхода через symlink.
- Субтитры не создавать приблизительно по длине текста без явно подтверждённого режима превью. Релиз требует фактических аудиотаймкодов.
- Для внешних моделей регистрировать название, версию, разрешённый источник, израсходованные кредиты и статус ручной проверки; не помещать приватные материалы в публичный git.

## B2. Выходной контракт

`output/<id>/`:
```
final.mp4
cover.jpg
subtitles.srt
qa_report.json
receipt.json
```
Пакет не называется выпущенным, пока этих файлов нет и они не проверены. Допускается `PREVIEW` без разрешения на публикацию; `approved_for_publication=false` по умолчанию всегда.

## B3. Критерии мастер-качества

- Контейнер MP4, H.264 yuv420p, 1080×1920, 24/30 fps, аудио AAC; видео без чёрного первого кадра.
- Закадровый текст на русском, высокая понятность и естественность. Нельзя считать русский результат валидным, если модель произнесла английский текст.
- Не меньше восьми связанных фотореалистичных сцен. У одного персонажа не должны меняться возраст, одежда и внешность без причины.
- Подложка по жанру, изменение настроения по сценам, музыкальный ducking, отсутствие перекрытия реплик.
- Субтитры — русские, внутри mobile-safe зоны, белый текст с читаемой обводкой; не менее 0.05 сек. на реплику и не за пределами реальной звуковой сцены.
- Индивидуальная цветная обложка, первый кадр MP4 тоже цветной.
- Полное декодирование видео через ffmpeg; файл с аудио и ожидаемой длительностью; копия мастер-исходников не удаляется.
- Видеопроизводство не может выдавать флаги прав/актерского качества автоматически; визуальная, редакционная и коммерческая оценка — внешние проверки.

## B4. Failure policy и идемпотентность

- Если нет изображения/голоса/таймкодов: `BLOCKED` с именем сцены и отсутствующего файла, без фиктивного MP4.
- Каждый рендер идёт в временный каталог, в целевую папку попадают только полностью проверенные файлы. По умолчанию запрещена перезапись существующего финала.
- Логи и квитанция указывают SHA-256 исходного скрипта, фактических ассетов, версии пайплайна и финального видео.
- Нет неразрешённых платных запросов, автоматической публикации или скрытого изменения Metricool/TikTok.
- QA разделяет машинные факты (`technical_pass`) и требующие просмотра критерии (`human_review_pending`).

## B5. Проверки и тесты

1. Проверить JSON/UTF-8/sha256 и приватность относительных путей; запрещать путь/симлинк наружу.
2. Не запускать генераторы и не создавать фиктивное аудио в `dry-run`.
3. Положительный тест: два небольших синтетических кадра и настоящие локальные тестовые WAV формируют реальный технический MP4 и SRT.
4. Отрицательные тесты: нет аудио, дубли ID, пустые сцены, отсутствующие таймкоды, несоответствие контрольной суммы, выход за длительность сцены.
5. Отдельно подтвердить master contract на реальных 8+ сценах, а не по учебному двусценному образцу.
6. Внутри CI нет запросов к платным API и нет притворной ручной `approved=true` отметки.

## B6. Ограничения текущего исполнения

Модуль монтажа может использовать FFmpeg/Pillow/NumPy и фактически предоставленные картинки, WAV и выравнивание. Он **не может** из одного текста гарантированно создать живую речь или фотореалистичное видео без генеративного провайдера, весов/ресурсов и лицензий. Не объявлять шесть роликов готовыми до проверки каждого MP4.
