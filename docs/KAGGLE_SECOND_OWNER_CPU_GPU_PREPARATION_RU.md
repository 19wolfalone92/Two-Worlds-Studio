# TWO WORLDS STUDIO — CPU/GPU второго участника Kaggle: подготовка без общего доступа

**Статус:** подготовлена независимая *локальная* проверка CPU/GPU. Удалённого подключения к аккаунту второго человека, проверки его API-токена, запуска его GPU или совместного использования квот здесь **нет**.

## Почему токен не используется

Kaggle Terms of Use (действуют с 22.06.2025) запрещают передачу аккаунтов без письменного разрешения и работу нескольких людей под одним Kaggle User ID. Даже если другой человек добровольно передал личный токен, это не превращает управление его аккаунтом в разрешённую схему.

Источники:
- https://www.kaggle.com/terms
- https://www.kaggle.com/docs/api

GitHub Secret с названием KAGGLE_API_TOKEN2 не требуется и **не считывается** этим комплектом. Старые производственные workflows используют только первый токен. Ни один из них не меняется этой веткой.

## Что реально подготовлено

- notebooks/TWO_WORLDS_KAGGLE_OWNER_CPU_GPU_CHECK.ipynb — полностью автономный код Kaggle для запуска **владельцем своего аккаунта**.
- tools/verify_compute_preflight.py — офлайн-проверка полученной квитанции, без сети.
- tests/test_kaggle_owner_compute.py — проверки формата, невозможности назвать отсутствующий GPU готовым, и CPU-прогон Notebook.
- .github/workflows/kaggle-owner-compute-preflight.yml — **CPU-only** CI, без секретов и GPU.

## Инструкция владельцу второго аккаунта

1. Войдите в **собственный** Kaggle через https://www.kaggle.com/code и создайте **Private Notebook**.
2. Перенесите в него код из TWO_WORLDS_KAGGLE_OWNER_CPU_GPU_CHECK.ipynb (ячейка Python). Не присылайте никому пароль или токен.
3. Сначала выберите Accelerator: None и запустите Notebook. Сохраните two_worlds_compute_preflight.json в приватном Kaggle Output как результат проверки CPU.
4. Если аккаунт имеет право на GPU и вы хотите проверить его, **самостоятельно** выберите ускоритель GPU и запустите Notebook второй раз. Короткий CUDA smoke test проверит, что GPU действительно виден текущему сеансу. GPU-сессия **может расходовать** бесплатную квоту, даже если вычисление очень короткое.
5. Скачайте квитанцию из Kaggle Output. Она содержит только числа о CPU, RAM, диске, моделях GPU и результаты короткой проверки. Передавайте только эту квитанцию, **не токен**, и желательно приватно.
6. Офлайн-проверка квитанции в студии:

   python -m tools.verify_compute_preflight /private/two_worlds_compute_preflight.json

## Что доказывает эта проверка

- CPU_CHECK_PASSED_GPU_NOT_READY — CPU-код выполнился, доступность CUDA не подтверждена.
- CPU_AND_GPU_CHECK_PASSED — в момент запуска NVIDIA GPU был доступен для *короткого* CUDA вычисления.
- Оба статуса **не подтверждают** возможность генерации Wan2.2/LTX, наличие свободной квоты, работоспособность API или способность одновременно рендерить несколько видеороликов.
- VRAM отображается **по каждой карте отдельно**: 2× T4 не означает единые 32 ГБ VRAM.

## Ограничения безопасности и перспективы интеграции

Никаких автоматических переключений личных токенов, обхода GPU-лимитов, передачи учётных данных в GitHub Actions или запуска задач от имени другого человека. Участники могут самостоятельно проводить разрешённые задания в своих аккаунтах и передавать готовые результаты друг другу. Для централизованного доступа к стороннему Kaggle-аккаунту сначала требуется согласовать с Kaggle разрешённую схему (например, авторизованное стороннее приложение, если оно соответствует условиям сервиса).
